# Изменение истории
## Amend
__Для редактирования последнего коммита используется git commit --amend. Его суть проста:__
1) Берется последний коммит
2) Оттуда берутся файлы
3) Добавляются снова в индекс (Если таких файлов уже не лежит в индексе. Если лежит то берутся свежие файлы с индекса)
4) СОздаетс новый коммит

__Можно использовать параметр --no-edit, чтобы оставить сообщение коммита без изменений__
__Примеры:__
1) git commit --amend -m "New message" - Последний коммит с новым сообщением
2) git commit --amend --author="Vlad" - Изменение автора последнего коммита
3) git commit --amend --date="Now" - Изменение даты коммита

__Двжиение по коммитам можно посмотреть командой git reflog__
__amend используем только если коммит не ушел в удаленный репозиторий, инача у тех кто уже успел его скачать будут конфликты__

## Rebase
__git rebase feature - переносит ветки с текущей ветки на указанную. Логика просто:__
1) Сначала находится общий коммит
2) Ветка которая вливается (текущая) - от нее берутся коммиты, которых нет в целевой и временно сохраняются
3) Указатель переходит на последний коммит указанной ветки (В примере feature)
4) Сохраненные на шаге 2 коммиты по 1 накладываются поверх коммитов с ветки feature
5) Разрешаются конфликты есть есть через git rebase --continue/git rebase --skip/ git rebase --abort

__rebase применяется в основном на локальных ветках. Если ветка уже в удаленном репозитории и кто то от нее ветвился, то нельзя делать rebase, тк история нарушится и у коллег будут конфликты__
__Если был неудачный rebase, то восстановится можно через git reset --hard <Указываем положение коммита с git reflog или относительно HEAD>__
__Если возник конфликт, то после его решения нужно добавлять файл в индекс git add . и после этого идти дальше git rebase --continue. Актуальное состояние rebase можно посмотреть в git status__

## Cherry-pick (Отбор сочных ягодок)
__Команда git cherry-pick позволяет в текущую ветку добавить указанные коммиты (Создаются новые, дублирующие указанные)__
__Пример git cherry-pick feature - Добавляем в текущую ветку последний коммит из ветки feature. Так же можно указать хеш коммита. ЧЕри пик именно создает коммиты а не переносит. Помни что когда мы создаем, то получается дубль, так что бывает всякое.__
__Опции:__
1) git cherry-pick -n feature - Не создавать новый коммит. Изменение которые были в коммите относительно текущих попадут в рабочую директорию и в индекс
2) git cherry-pick ed123 ds1231 xsa2131231 - Переносим 3 коммита по хешу в текущую ветку
3) git cherry-pick ed123..ed321 - Переносим все коммиты от ed123 (Не включительно) до ed321
4) git cherry-pick ed123^..ed321 - Переносим все коммиты от ed123 (Включительно) до ed321
5) git cherry-pick feature~3..feature - Перенос последних 3 коммитов из ветки feature
6) git cherry-pick m 1 ed123 - Переносим коммит 1ого родителя (Коммит ветки в которую мержили) с мердж коммита

__При переносе коммитов могут быть конфликты. Команды для решения такие же как и для rebase:__
1) git cherry-pick --continue - Продолжаем (После добавления в индекс)
2) git cherry-pick --skip - Пропускаем коммит
3) git cherry-pick --abort - Отменяет черри пик
