# Ветки и слияния
## Создание ветки
__Создать ветку можно 3мя способами__
1) Создать ветку не переключаясь на нее - git branch feature
2) Создать ее и переключиться на нее git switch -c feature
3) Старый способ создать и переключиться git checkout -b feature

## Удаление ветки
__Удалить ветку можно 2мя способами__
1) Мягкое удаление через git branch -d feature - Удаляет, если ветка смержена в другую ветку, чтобы данные не потерялись
2) Принудительное удаление через git branch -D feature - Удаляет ветку насильно

## Показать информацию о ветках
__Узнать какие есть ветку локально можно через git branch__
__Чтобы увидеть ветки, которые отличаются по коммитам от текущей, можно указать так git branch --no-merged__
__Чтобы увидеть ветки идентичные текущей по коммитам используется git branch --merged__

## Переключиться на уже существующую ветку можно 3мя способами:
1) git checkout feature
2) git switch feature
3) "git switch -" - Переключает на предыдущую ветку

## Слияние веток

__Есть 2 вида слияния через git merge__
1) fast-forward - когда 1 ветка является продолжэение логмческим другой ветки по коммитам. В таком видео смлияния новый коммит не создается, а просто история коммитов с одной перехдит в другую. Можно это явно обойти, заставив git создать все таки отдельный коммит через параметр --no-ff
2) three-way-merge - когда в обоих ветках от самого первого коммита пошли отдельные свои коммиты. При таком слиянии гит анализириует 3 точки - общий коммит, конец 1ой ветки и конец 2ой ветки

__Команда для слияния git merge <Название ветки которую вливаем в активную>__
__Так же это можно сделать через git rebase feature - в данном примере все коммиты с текущей ветки будут перенесены поверх ветки feature. Каждый коммит будет накладывается друг за другом__

## Отмена коммитов
__Есть 2 способа отменить коммиты__
1) Неоплубликованный коммиты - git reset --hard HEAD~1 - Удаляем последний коммит и возвращается к указанному. В данном случае на 1 коммит назад. Так же можно указать хеш коммита
2) Опубликрованные коммиты - git revert -m 1 HEAD - Создается новый коммит, где октатаны изменения для коммита слияния. Указывает в HEAD что мы отменяем. -m 1 нужен для коммитов слияния.

## Разрешение конфликтов
__Есть 3 типа конфликтов:__
1) Внутри файлов - 1 и тот же файл 1 и те же строки разные в разных ветках
2) Конфликт удаленных файлов - В 1ой ветки файл удален в другой переименовали
3) Конфликт переименованных файлов  - В 1ой ветке файл называется одним именем, в другой другим

__Для решения конфликтов git будет помечать 2 версии ----> HEAD это начало нашей ветки, ========== - разделитель между версиями <--------feature ветка которую влвиаем. Для решения конфликта достаточно оставить какую от версиб или написать свою, убрать разделители, добавить файл в индес и сделать коммит__
__Если конфликт возник на этапе git rebase, то решаем конфликт по каждому коммиту вручную. Во время решения конфликтов доступны команды git rebase --continue - Продолжить накладывать коммиты/ git rebase --skip - Пропустить проблемный коммит/ git rebase --abort -- отменить rebase__

__Так же можно в процессе решения конфликта отменить слияние через git merge --abort__
__Статус слияния так же отображается через git status__
