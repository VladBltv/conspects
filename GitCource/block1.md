# Основы Git
### Git - Система контроля версий. Нужна для совместной работы над проектом, созданием разных версий кода, безопасного отката кода, истории. Часто на действия с Git триггерится выполнение пайаплайна.
## Установка Git на разных версиях ОС
### Windows
__На винду скачивается установочник и так ставится.__
### Linux
__На дистрибутивах Debian/Ubuntu/Kali ставится через пакетный менеджер apt. Команда: sudo apt update && sudo apt install git -Y__
__На дистрибутивах RHEL(Red Hat Enterprise Linus) или CentOS (Community Enterprise OS) через менеджер dnf (dendified yum), а в старых версиях через yum (YellowDog Modified). Команда: sudo dnf install git -y__
### MacOS
__Устанавливаем через пакетный менеджер HomeBrew: brue install git__

## Настройка Git
__Настройка идет через конфиг.__
1) git config --global user.name <Имя> - Задать имя юзера
2) git config --global user.email <Почта> - Задать почту юзера

__Тут global это один из вариантов и показывает на каком уровне мы задаем настройки. Всего 3 уровня: system(Задаем для всех проектов всех юзеров этой машины), global(Задаем для всех проектов текущего юзера), без флага (для текущего репозитория).__
__Так же можем задать алиасы, которые позволят сократить написание. Например:__
1) git config --global alias.cm commit - позволит писать git cm
2) git config --global alias.ch checkout - позволит писать git ch master

__Генерация ключей__

__Мы можем генерировать ssh ключ (приватынй и публичный). Для этого выполняются команды в GitBash__

__ssh-keygen -t ed25519 -C "email@email.ru" - ssh-keygen утилита для генерации ключей, -t ed25519 - это вид шифрования, -C "mail@mail.ru" - это просто коммент чтобы человек который открыл ключ понял кому он принадлежит__

__Далее, чтобы не вводить каждый раз ключ и пароль, запуска агента у которого наш ключ будет крутиться__

__eval "($ssh-agent -S)"__

__ssh-agent -S - Запуска агента в память + ключ -S (Shell) выводит его настройки в консоль вида KEY=12345. Это нужно чтобы eval смог выполнить эти команды и подружить нашу консоль с агентом__
__eval выполняет команды, полученные при выводе команд от агента__

__ssh-add ~/.ssh/id_ed25519 - Добавляем приватный ключ в агента__

__cat ~/.ssh/id_ed25519.pub - Выводим публичный ключ в консоль__

__Так же мы можем получить список настроек - git config --list__

## Терминология, История, Понятия
__Git создал Линус Торвальдс в 2005 года, тк на тот момент бесплатный BitKeeper перестал быть бесплатным из за соры основателей. НА рынке небыло подходящих систем контроля версий (VCS - Version Control System) и Линус за 10 дн создал свою. Тогда в основном были центразиованные VCS, что накладывало некие неудосбтва. Вообщем Линусу это непонравилось и он создал свою распределенную VCS известную, как Git.__
__Так как Git система является распределенной, то в сухом остатки мы имеем ситуацию, где у всех разработчиков, локально хранятся вся история изменений и нет какого то 1ого хранилища. Да есть системы типо GitLab, GitHub, Bitbucket, но архитектурно у каждого хранится вся история, что является безопасным.__
__Вообще Git использует такой механизм, когда при изменениях делается снимок текущего состояния проекта (коммит) и все это происходит локально, что позволяет работать без интернета. Гит сжимает файлы, зкидывает в папку .git/objects и там их хранит - это называется blob. Так же гит сохраняет отдельно файл типа tree, то есть снимок текущего состояния проекта - дерево. И наконец туда же сохраняется еще 1 вид файлов это коммит - то есть изменения и ссылки на файлы. Глобально еслив проекте что то меняется гит в коммите сохраняет инфу о тех файлах которые не изменились и инфу о новых файлах. Если проще то коммит это ссылки на определенный вид файлов, которые когда то были и разные коммиты это разные наборы таких файлов в разном состоянии. Название для таких файлов получается из хеша, который прогоняется через криптографический алгорит SHA-1, в современном виде через SHA-256.__
__Вообще есть 3 зоны в Git через которые проходят изменения:__
1) Рабочая директория - то где редактируем файл
2) Индекс - то куда загоняем файлы через git add (На этом этапе в папку object уже попадают файлы blob, для безопасного хранения)
3) Репозиторий - место хранения всех коммитов (На этом шаге в objects попадают файлы типа tree и commit)

__Есть разные виды VCS, основных 3__
1) Локальная - все версии файлов хранятся локально. Из минусов, забивается память и одна точка отказа, из плюсов - простота
2) Централизированная (CVCS - Central Control Version System) - Все файлы лежат на сервере. Там старые системы обработки, где изменения хранятся в отдельных файлах, где прописывается мол в файле 1 было изменение строки 2 и тд. В таком подходе идет долгая обработка тк за каждым файлом следят и редактируют отдельно без сжатия + задержки на общение между клиентом и сервером. А если переименовать роджительскую папку то там будет куча изменений. И алгоритм получения нужной версии такой - Берется изначальная и накидывается каждое изменение друг за другом пока не дойдет до нужной версии и так каждый раз.У Git совсем другая система. Там сжатые файлы целиком и хранение локальное + отдельные новые объекты формируются только в случае изменения файлов иначе остаются ссылки на старые.
3) Распределенная (DVCS - Distributed Control Version System) - Все файлы лежат у каждого юзера. Нет центральной точки отказа. Пример - Git. Плюсы - Гибкость, Скорость, Удобство.

## Ветки, коммиты и репозиторий
__В Git 3 основные сущности: Ветка, коммит и репозиторий__
__Репозиторий это папка в которой обычно хранятся рабочие файлы. В репозитории всегда есть скрытая папка .git, где хранятся все коммиты, сжатые файлы при коммите, инфа о проекте и тд__
__Ветка - это просто указатель на последний коммит в текущем ветвлении. Просто маленький файлик указывающий на какой то коммит__
__Коммит - это снимок текущего состояния проекта. В коммите хранится инфа о состоянии проекта, его хеш, автор, сообщение и самое важное хеш родителя. Может быть несколько родителей. Такое происходит при мерже, когда объединяются 2 ветки. При мерже создается 1 новый коммит с изменениями из новой ветки + правками конфликтов. Этот коммит указывает на хешы 2ух родителей__
__Так же есть такой указатель как HEAD. Он указывает на текущий коммит. Если ты на ветке какой то, то он указывает на ветку, а ветка на коммит,если ты переключишься на какой то другой коммит, то HEAD будет указывать на него (ветка из этой схемы уходит), но указатель ветки все так же останется на последнем коммите своего ветвления.__
