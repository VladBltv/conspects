# Удаленные репозитории
## clone и add origin
__Команды для работы с удаленным репозиторием:__
1) git remote add origin <http url> - Добавить ссылка на удаленный репозиторий
2) git remote -v - Показать подробную инфу о связанных удаленных репозиториях
3) git clone <http url> my-project - Клонировать репозиторий в папку my-project(сама создастся в текущей папке)
4) git clone --depth 1 <http url> - Клонировать репозиторий с 1им коммитом с дефолтной ветки. Можно явно указать ветку через --branch и --single-branch
5) git clone --branch develop --single-branch <https url> - Клонировать репозиторий только с 1ой веткой develop (То что надо скачать 1 ветку указывает --single-branch), а то что нужна именно ветка develop указывает --branch develop.
6) git push origin main - загрузить коммиты с ветки main в удаленный репозиторий под алиасом origin
7) git remote show origin - покажет подробности по удаленному репозиторию с алиасом origin
8) git remote rename origin origin2 - Переименовать алиас у удаленного репозитория origin
9) git remote set-url origin <new url> - изменить url для удаленного репозитория под алиасом origin
10) git remote rm origin - удалить связь с удаленным репозиторием origin
11) git push -u origin master - Первая отправка коммитов. Через -u или --set-upstream будет создана связь и все последующие gut push полетят туда
12) git remote set-url --push origin <url> - Для push команды поставит загрушку на удаленный репозиторий вместо ссылки и если это будет ориг например как 1 из репозиториев (например ты форкнул тобиж создал копию и под origin у тебя оригинал и ты туда не хочш ниче пушить, то ты ставишь туда заглушку), то этот ориг не изменится. Но ты сможешь делать с него fetch и подкачивать обновы.
13) git remote set-url --upstream origin <url> - Ставить заглушку для fetch и Push с origin. После этого можно через --push добавить норм адрес и получится что фетч будет збаблочен а пуш доступен. Противиоположность пункту выше.

## Push, Pull, Fetch
__Есть 3 вида веток: локальная, с удаленного репозитория и удаленная ветка__
__Эти ветки обозначаются по разному. Например: feature - Локальная. origin/feature - удаленная__
__Для работы с удаленными репозиториями используют в основном 3 команды:__
1) git fetch - Подтягивает с удаленного репозитория актуальные коммиты, если есть. Локальные указатели веток не меняются, но появляются новые с удаленного репозитория аля origin/master. С таким подходом можно подтянуть актуальную версию не изменяя особо состояние веток. Полезно для просмотра изменений и контроля.
2) git pull - подтягивает изменения с удаленного репозитория и сразу же их применяет. Грубо говоря происходит git fetch и сразу git merge, если можно сделать ff merge иначе делает rebase перекидывая коммиты с локальной ветки поверх новых с удаленного репозитория. Могут быть конфликты и тд.
3) git push - пушит новые коммиты в удаленный репозиторий если есть. При первом пуше надо связать с удаленным репозиторием, чтобы была связь. Связывают через git push -u (это upstream) origin main. Далее можно просто push

__Чтобы посмотреть насколько отстает локальная ветка от удаленной (актуально только для связанных) используется git status -a (то есть all)__
__Если при push нельзя выполнить ff слияние, то git отклонит пуш. Такое бывает если кто то уже влил в удаленную ветку коммиты, которых у тебя нет локально. Так что в таком случае только подливать мастер локально__
__Чтобы насильно переписать коммиты в удаленном репозитории, можно использовать git push --force origin master. Но тогда все коммиты который нет локально потеряются__

## Удаленные ветки
__Удалить ветку на удаленном репозитории, которая была удалена локально можно через git push origin --delete feature__
__Чтобы локально удалить ветки, которые остались после подтягивания с удаленного репозитория, например origin/feature, можно удалить через git remote --prune origin__
