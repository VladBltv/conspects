# Удаленные репозитории
## clone и add origin
__Команды для работы с удаленным репозиторием:__
1) git remote add origin <http url> - Добавить ссылка на удаленный репозиторий
2) git remote -v - Показать подробную инфу о связанных удаленных репозиториях
3) git clone <http url> my-project - Клонировать репозиторий в папку my-project(сама создастся в текущей папке)
4) git clone --depth 1 <http url> - Клонировать репозиторий с 1им коммитом с дефолтной ветки. Можно явно указать ветку через --branch и --single-branch
5) git clone --branch develop --single-branch <https url> - Клонировать репозиторий только с 1ой веткой develop (То что надо скачать 1 ветку указывает --single-branch), а то что нужна именно ветка develop указывает --branch develop.
6) git push origin main - загрузить коммиты с ветки main в удаленный репозиторий под алиасом origin
7) git remote show origin - покажет подробности по удаленному репозиторию с алиасом origin
8) git remote rename origin origin2 - Переименовать алиас у удаленного репозитория origin
9) git remote set-url origin <new url> - изменить url для удаленного репозитория под алиасом origin
10) git remote rm origin - удалить связь с удаленным репозиторием origin
11) git push -u origin master - Первая отправка коммитов. Через -u или --set-upstream будет создана связь и все последующие gut push полетят туда
12) git remote set-url --push origin <url> - Для push команды поставит загрушку на удаленный репозиторий вместо ссылки и если это будет ориг например как 1 из репозиториев (например ты форкнул тобиж создал копию и под origin у тебя оригинал и ты туда не хочш ниче пушить, то ты ставишь туда заглушку), то этот ориг не изменится. Но ты сможешь делать с него fetch и подкачивать обновы.
13) git remote set-url --upstream origin <url> - Ставить заглушку для fetch и Push с origin. После этого можно через --push добавить норм адрес и получится что фетч будет збаблочен а пуш доступен. Противиоположность пункту выше.
